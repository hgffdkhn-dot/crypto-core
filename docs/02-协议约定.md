# EnChat 协议约定（v1）

> 与 `crypto-core/src/main/kotlin/com/enchat/protocol/Protocol.kt` 一一对应；两端共享，禁止各自实现一份。

---

## 1. 通用约定

- 传输：REST（`https://host/api/v1/...`）用于一次性操作；WebSocket（`wss://host/ws`）用于实时双向
- 编码：JSON（UTF-8）；二进制字段用 **Base64（标准字母表，不带换行）**；字节序统一**大端**
- 时间：ISO-8601 / UTC，或毫秒时间戳（字段名以 `At` 结尾时为毫秒时间戳）
- 所有 WebSocket 业务帧都承载在**传输层加密帧**内（见 §3）
- 单帧上限 1 MB，超出的消息请分片或改走对象存储 + URL
- 客户端必须在请求头带 `X-Client-Version`；服务端对过旧版本返回 `1001 VERSION_TOO_OLD`

---

## 2. REST 接口

### 2.1 注册

```http
POST /api/v1/auth/register
{ "username": "alice", "password": "10203040", "nickname": "阿丽" }
```
```json
200 {
  "userId": 1001, "uid": 100000001,
  "accessToken": "<jwt>", "refreshToken": "<jwt>",
  "expiresIn": 7200
}
```
错误：`1002 USERNAME_TAKEN`、`1003 WEAK_PASSWORD`、`400 BAD_REQUEST`

> 注册成功后客户端**立即生成身份密钥并上传**（§2.4），否则无法启用 E2EE。

### 2.2 登录

```http
POST /api/v1/auth/login
{ "username": "alice", "password": "10203040" }
```
返回同上。失败：`1004 WRONG_CREDENTIALS`（连续失败触发限速 `429 RATE_LIMITED`）。

### 2.3 资料与头像

```http
PATCH /api/v1/me            { "nickname": "...", "signature": "..." }
POST  /api/v1/me/avatar     multipart, ≤2MB → { "avatarUrl": "..." }
GET   /api/v1/users/{uid}   → { "uid":..., "username":..., "nickname":..., "avatarUrl":... }
```

### 2.4 密钥分发（E2EE 前置）

```http
POST /api/v1/keys/upload
{
  "identityEd25519Pub": "<b64 32B>",
  "identityX25519Pub":  "<b64 32B>",
  "signedPreKey": { "id": 11, "publicKey": "<b64 32B>", "signature": "<b64 64B>" },
  "oneTimePreKeys": [ { "id": 1, "publicKey": "<b64 32B>" }, ... ]   // 建议一次补 100 个
}

GET /api/v1/keys/bundle?uid=100000002
→ {
  "userId": 1002,
  "identityEd25519Public": "<b64>", "identityX25519Public": "<b64>",
  "signedPreKeyId": 11, "signedPreKeyPublic": "<b64>", "signedPreKeySignature": "<b64>",
  "oneTimePreKeyId": 7, "oneTimePreKeyPublic": "<b64>"      // 无 OPK 时这两个字段为 null
}
```
- OPK **用完即焚**（`consumed=true`），服务端 OPK 低于阈值时主动推送补货提醒
- SPK 默认 7 天轮换；客户端应在每次登录时检查并轮换

## 3. WebSocket 传输层

### 3.1 握手（连接建立后最先完成）

```
C → S : clientHello = clientEphPub(32) || clientNonce(16)                [48B 二进制]
S → C : serverHello = serverEphPub(32) || serverNonce(16) || sig(64)     [112B 二进制]
```
随后所有业务帧：
```
frame = version(1) || seq(8) || noncePrefix(4) || AES-256-GCM(payload)
```
- `seq` 每方向从 0 起严格递增，接收方校验相等，不符即断开（`1013 TRANSPORT_DECRYPT_FAILED`）
- 客户端必须校验 `serverHello` 签名，且服务器长期公钥来自内置 pin

### 3.2 鉴权

```json
C → S { "t": 2, "token": "<jwt>", "protocolVersion": 1, "deviceId": "<uuid>" }
S → C { "t": 3, "ok": true, "uid": 100000001, "serverTime": 1730000000000, "latestSeq": 8123 }
```
`latestSeq` 用于客户端增量同步（§6）。

### 3.3 心跳

客户端每 25s 发 `{"t":4,"ts":<ms>}`，服务端回 `{"t":5,"ts":<ms>}`；60s 无心跳服务端断开。

---

## 4. 业务帧通用结构

```json
{ "t": 10, "rid": "uuid-用于请求响应配对", "ts": 1730000000000, "payload": { ... } }
```
- `t` = `FrameType.code`
- 需要应答的请求带 `rid`；应答帧回同一 `rid` + `ok` + 可选 `err`（`ErrorCode.code`）

## 5. 消息收发

### 5.1 标准模式（传输层加密，服务器明文落库）

```json
C → S {
  "t": 10,
  "rid": "r1",
  "payload": {
    "conversationId": 9001,
    "kind": 1,
    "clientMsgId": "本地去重 id",
    "text": "你好"            // 服务器解密后明文入库
  }
}
S → C { "t": 12, "rid": "r1", "payload": { "serverMsgId": 5521, "serverSeq": 8124, "createdAt": 1730000000000 } }

S → 接收方 { "t": 11, "payload": { "conversationId": 9001, "serverMsgId": 5521, "senderId": 1001,
                                   "kind": 1, "text": "你好", "createdAt": ..., "serverSeq": 8124 } }
```

### 5.2 端到端模式

```json
C → S {
  "t": 10,
  "rid": "r2",
  "payload": {
    "conversationId": 9002,        // encryptionMode = 2 的会话
    "kind": 1,
    "clientMsgId": "...",
    "e2ee": {
      "sessionId": "<b64 16B>",    // 冗余携带，便于服务端路由与排障（不解密）
      "ciphertext": "<b64>"        // E2EE 线格式（version||sessionId||chainIndex||ct）
    }
  }
}
```
服务端**不解密 `e2ee.ciphertext`**，原样入库并转发；保留期默认 30 天（未拉取即删除）。

### 5.3 建立 E2EE 会话

```
Alice                          Server                          Bob
  │ GET /keys/bundle?uid=Bob ──►│──── 转发 Bob 的 PreKeyBundle ──►│
  │ createAsSender() → SK + InitMessage                           │
  │ SEND_MESSAGE kind=10 (E2EE_INIT, payload=InitMessage 二进制) ─►│──► createAsReceiver() → 同一 SK
  │◄──────────────────── MESSAGE_ACK ─────────────────────────────┤
```
- 双方可能同时发起（并发会话）：以 `sessionId` 区分；客户端策略——若本地已有会话且收到新的 InitMessage，比较 `sessionId` 字典序，**保留较大者**，另一条废弃（需在 UI 上提示"会话已重建"）
- `kind=10`（E2EE_INIT）消息不在聊天界面展示

### 5.4 群聊 Sender Key

```
发送方：epoch 不变时直接加密广播；成员变动时 epoch+1 → 新 chain → 逐成员分发
分发帧：SEND_MESSAGE kind=11，payload = 用双边 E2EE 会话加密后的 distributionPayload(57B)
接收方：收到后构造 ReceiverKeyState，之后按 (groupId, senderId, epoch, iteration) 解密
```

## 6. 断线重连与同步

```json
C → S { "t": 14, "rid":"s1", "payload": { "afterSeq": 8123, "limit": 200 } }
S → C { "t": 15, "rid":"s1", "payload": { "messages": [...], "hasMore": false, "latestSeq": 8130 } }
```
- 客户端本地保存已消费的 `serverSeq`；重连后从 `afterSeq` 拉取
- 重连必须**重新做传输层握手**（新 ephemeral 密钥），不得复用旧会话
- E2EE 消息乱序到达由棘轮层吸收；若索引超出乱序窗口（1000），客户端应显式提示"该消息无法解密"而不是静默丢弃

## 7. 好友与群

```json
{ "t": 20, "payload": { "toUid": 100000002, "message": "我是阿丽" } }   // 发送好友请求
{ "t": 21, "payload": { "requestId": 1, "fromUid":..., "fromNickname":..., "message":... } }  // 事件推送
{ "t": 22, "payload": { "requestId": 1, "accept": true } }
{ "t": 24, "payload": { "friendUid": 100000002 } }
{ "t": 25, "payload": { "friends": [ { "uid":..., "nickname":..., "avatarUrl":..., "online": true } ] } }

{ "t": 30, "payload": { "title": "周末爬山", "memberUids": [100000002, 100000003], "encryptionMode": 2 } }
{ "t": 31, "payload": { "conversationId": 7001, "uids": [...] } }   // 邀请 → 触发 epoch+1
{ "t": 33, "payload": { "conversationId": 7001 } }                  // 退群 → 触发 epoch+1
{ "t": 34, "payload": { "conversationId": 7001, "epoch": 3, "members": [...] } }
```

## 8. 错误码

| code | 常量 | 客户端处理 |
|---|---|---|
| 400 | BAD_REQUEST | 提示 + 记录日志 |
| 401 | UNAUTHORIZED | 刷新 token，失败则登出 |
| 403 | FORBIDDEN | 提示无权限 |
| 404 | NOT_FOUND | 提示资源不存在 |
| 409 | CONFLICT | 刷新本地状态后重试 |
| 429 | RATE_LIMITED | 指数退避，禁止无脑重试 |
| 500 | INTERNAL | 提示稍后重试 |
| 1001 | VERSION_TOO_OLD | 强制更新 |
| 1002 | USERNAME_TAKEN | 注册页行内提示 |
| 1003 | WEAK_PASSWORD | 注册页行内提示 |
| 1004 | WRONG_CREDENTIALS | 登录页提示（不区分用户名/密码错误） |
| 1005 | INVALID_UID | 搜索页提示 |
| 1006–1008 | 好友相关 | 行内提示 |
| 1009 | GROUP_FULL | 提示上限 500 |
| 1010 | PREKEY_EXHAUSTED | 提示对方稍后再试，客户端自动重试建会话 |
| 1011 | E2EE_REQUIRED | 会话已升级为 E2EE，禁止降级发送 |
| 1012 | MESSAGE_TOO_LARGE | 拆分或改文件 |
| 1013 | TRANSPORT_DECRYPT_FAILED | 断开重连，不要反复重试 |

## 9. 限速（服务端必须实现）

| 场景 | 限制 |
|---|---|
| 登录失败 | 同账号 5 次/15 分钟；同 IP 30 次/15 分钟 |
| 注册 | 同 IP 5 次/小时 |
| 好友请求 | 同账号 20 次/天 |
| 发消息 | 同账号 30 条/秒，突发 100 |
| 建群 | 同账号 5 个/天 |
| 上传预密钥 | 同账号 10 次/小时 |

## 10. 兼容与演进

- 线协议版本 `Protocol.VERSION = 1`；不兼容变更递增，服务端拒绝过旧客户端（`1001`）
- E2EE 消息头含 `version` 字节，未来升级算法可平滑共存
- 新增可选字段必须允许缺失；删除字段需先走"写入但忽略"两个版本

---

## 11. 已知限制（诚实列出）

1. 传输层重放防护依赖**单条有序流**；若将来改用 UDP/QUIC 或多路并发连接，需替换为滑动窗口
2. E2EE 无后向保密（DH 棘轮缺失）：会话密钥若被完整窃取，之后消息仍可被解，直到重建会话
3. 服务器可整包替换公钥包实施主动 MITM，只能靠 Safety Number 带外核验发现
4. E2EE 不隐藏元数据（通信关系、时间、频率、消息大小）
5. 多设备场景下 sender key 与会话密钥的分发尚未定义（v1 仅单设备）
