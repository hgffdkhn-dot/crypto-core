# EnChat 服务端部署指南

面向「已经跑通客户端、要把它放到真实服务器上」这一步。本文假定你有一台能公网访问的 Linux 主机（云 VPS 即可）。

---

## 0. 先看清这几条，能省掉大部分返工

| # | 事项 | 为什么 |
|---|---|---|
| 1 | **服务器公钥必须 pinning 进客户端** | 服务端首次启动会生成长期身份密钥。客户端硬编码的 pin 与之不符会**直接连不上**。所以顺序是：先部署服务端 → 取公钥 → 填进 `app/build.gradle.kts` → **重新编译客户端**。这一步做完前，客户端连不上是正常的。 |
| 2 | **`ENCHAT_PEPPER_B64` 上线后不能改** | 它是 Argon2id 的 pepper。改了所有已注册用户的口令哈希全部失效，只能逐个重置。生成后立刻备份到密码管理器。 |
| 3 | **`server-identity.key` 比数据库还重要** | 数据库重建 = 用户重新注册；密钥丢失 = **所有已安装客户端永久连不上**，必须发新版更新 pin 才能救回。务必备份。 |
| 4 | **生产必须用 PostgreSQL，不能用 H2** | 当前默认 `jdbc:h2:mem:` 是内存库，进程一停数据全没，仅供本地与集成测试。 |
| 5 | **Nginx 的 WebSocket Upgrade 头不能漏** | 漏了会表现为客户端一直显示「连接中…」，但 HTTP 接口一切正常，很容易误判。 |

---

## 1. 前置条件

- Linux 主机（x86_64），**内存 ≥ 2 GB**（Argon2id 单次派生需 64 MiB 堆，注册/登录并发时要留出余量）
- 一个域名，A 记录指向该主机（用于 HTTPS 证书）
- 开放端口：**80**（证书校验）、**443**（服务）。8080 只在回环监听，不必对外
- 软件：`docker` + `docker compose` v2、`nginx`、`certbot`、`curl`、`openssl`

```bash
# Ubuntu 22.04/24.04 快速安装
sudo apt update && sudo apt install -y nginx curl openssl certbot python3-certbot-nginx
curl -fsSL https://get.docker.com | sudo sh
sudo usermod -aG docker "$USER"   # 重新登录后生效
```

## 2. 三种部署方式，选一个

| 方式 | 适用 | 复杂度 |
|---|---|---|
| **A. Docker Compose（推荐）** | 大多数场景；自动带起 PostgreSQL | 低 |
| **B. systemd 直跑** | 已有 PostgreSQL、不想上容器 | 中 |
| **C. 手动 jar** | 临时验证、调试 | 低 |

### A. Docker Compose（推荐）

一键脚本会把下面所有步骤串起来：

```bash
sudo ./deploy/deploy.sh chat.example.com
```

脚本会：生成密钥 → 构建镜像 → 启动 Postgres + Server → 打印服务器公钥 → 申请证书 → 配 Nginx → 健康检查。

想手动分步执行：

```bash
cd deploy
cp env.example .env
openssl rand -base64 24 | tr -d '/+=' | head -c 24   # → DB_PASSWORD
openssl rand -base64 32                               # → PEPPER_B64
# 把上面两个值填进 .env，PUBLIC_BASE_URL 填 https://你的域名
sed -i 's|https://chat.example.com|https://你的域名|' .env
docker compose --env-file .env up -d --build
docker compose logs -f server
```

### 0. 先拿到服务端分发包

三种途径，任选：

**① 从 CI 下载（推荐）**

- 手动触发：GitHub 仓库 → **Actions** → 左侧选 `CI` → 右上角 **Run workflow** → 分支选 `main` → 运行。
  跑完后在当次运行的 Artifacts 里下载 `enchat-server-dist`（内含 `enchat-server-<ref>.tar.gz`）。
- 打 tag 自动触发：`git tag v0.9.0 && git push origin v0.9.0`

```bash
# 解压到服务器
scp enchat-server-main.tar.gz user@your-server:/opt/
ssh user@your-server
cd /opt && mkdir -p enchat && tar xzf enchat-server-main.tar.gz -C enchat
# 得到 /opt/enchat/bin/server 与 /opt/enchat/lib/*.jar
```

**② 服务器上直接构建**（需要装 JDK 17 + Gradle）

```bash
gradle :server:installDist
```

**③ Docker 方式**（下面 A）不需要分发包，镜像里自己构建。

> 注：CI 里的 `server-dist` job 只在 **打 `v*` tag** 或 **手动 workflow_dispatch** 时运行，
> 普通 push 到 main 会跳过它 —— 这是刻意的，避免每次提交都花几分钟打分发包。

### B. systemd 直跑（已有 PostgreSQL）

```bash
# 1) 建库建用户
sudo -u postgres psql -c "CREATE USER enchat WITH PASSWORD '强口令';"
sudo -u postgres psql -c "CREATE DATABASE enchat OWNER enchat;"

# 2) 拿到分发包（见上一节 0）后解压到 /opt/enchat
#    sudo tar xzf enchat-server-main.tar.gz -C /opt/enchat

# 3) 部署
sudo rsync -a server/build/install/server/ /opt/enchat/
sudo useradd -r -d /opt/enchat -s /usr/sbin/nologin enchat || true
sudo mkdir -p /var/lib/enchat/keys /var/lib/enchat/uploads /etc/enchat
sudo chown -R enchat:enchat /var/lib/enchat /opt/enchat

sudo cp deploy/enchat.env.example /etc/enchat/enchat.env
sudo ${EDITOR:-vi} /etc/enchat/enchat.env     # 填好口令、pepper、域名
sudo chown enchat:enchat /etc/enchat/enchat.env && sudo chmod 600 /etc/enchat/enchat.env

sudo cp deploy/enchat.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now enchat
journalctl -u enchat -f
```

### C. 手动 jar（临时验证）

```bash
gradle :server:installDist
ENCHAT_JDBC_URL='jdbc:postgresql://127.0.0.1:5432/enchat' \
ENCHAT_DB_USER=enchat ENCHAT_DB_PASSWORD='...' \
ENCHAT_PEPPER_B64="$(openssl rand -base64 32)" \
ENCHAT_SERVER_KEY_FILE=./data/server-identity.key \
ENCHAT_UPLOAD_DIR=./data/uploads \
  ./server/build/install/server/bin/server
```

## 3. 关键配置说明

全部走环境变量，默认值**只适合本地**。

| 变量 | 说明 | 生产建议 |
|---|---|---|
| `ENCHAT_JDBC_URL` | JDBC 连接串 | `jdbc:postgresql://db:5432/enchat`（Docker）或 `jdbc:postgresql://127.0.0.1:5432/enchat` |
| `ENCHAT_DB_USER` / `_PASSWORD` | 数据库凭据 | 专用账号，不要用 `postgres` 超级用户 |
| `ENCHAT_DB_POOL` | HikariCP 池大小 | 8；并发高可调到 16，但别超过 Postgres 的 `max_connections` |
| `ENCHAT_PEPPER_B64` | Argon2id pepper | `openssl rand -base64 32`。**上线后不可改** |
| `ENCHAT_SERVER_KEY_FILE` | 服务器长期身份密钥路径 | 挂到持久卷，权限 600，**必备份** |
| `ENCHAT_UPLOAD_DIR` | 头像存储目录 | 挂持久卷；丢了大不了头像没了 |
| `ENCHAT_PUBLIC_BASE_URL` | 对外地址 | `https://你的域名`，用于头像 URL 拼接 |
| `ENCHAT_E2EE_RETENTION_DAYS` | 端到端密文保留天数 | 默认 30 |
| `JAVA_OPTS` | JVM 参数 | `-Xms512m -Xmx1500m -XX:+UseG1GC` |

> 服务端启动时会打印两行公钥（见第 4 节）。首次启动自动生成密钥文件；**只要文件在，重启不会重新生成**，公钥保持不变。

## 4. 取公钥 → 回写客户端（必做）

服务端启动日志里：

```
服务器长期公钥（客户端必须 pinning）：
  ed25519=xxxxxxxxxxxxxxxxxxxx
  x25519 =yyyyyyyyyyyyyyyyyyyy
```

填进 `app/build.gradle.kts`：

```kotlin
buildConfigField("String", "DEFAULT_HOST",            "\"https://你的域名\"")
buildConfigField("String", "SERVER_ED25519_PUB_B64",  "\"上面 ed25519 的值\"")
buildConfigField("String", "SERVER_X25519_PUB_B64",   "\"上面 x25519 的值\"")
```

然后**重新编译客户端**。留着 `REPLACE_WITH_YOUR_SERVER_KEY` 占位符的话，App 会启动即抛异常 —— 这是刻意的，宁可显式失败也不能静默接受任意服务器。

---

## 5. 部署后自检

```bash
./deploy/verify.sh https://chat.example.com
```

会依次检查：健康检查、TLS 证书有效期、注册/登录、`/me` 鉴权、未鉴权被拒、弱口令拒绝、WebSocket 握手（101）、数据库表是否齐全。

**全绿才算真的部署好了**。特别留意 WebSocket 那项 —— 它失败时 REST 接口仍然正常，很容易漏掉。

## 6. 备份

```bash
./deploy/backup.sh /mnt/backups

# crontab：每天凌晨 3 点
0 3 * * * /opt/enchat/deploy/backup.sh /mnt/backups >> /var/log/enchat-backup.log 2>&1
```

备份内容：PostgreSQL 全量 dump（gzip）+ 服务器身份密钥 tar.gz，保留 14 天。

**强烈建议把备份同步到异地**（对象存储或另一台机器）。密钥文件只有几 KB，但丢了代价极大。

恢复数据库：

```bash
gunzip -c enchat-db-YYYY-MM-DD.sql.gz | docker compose exec -T db psql -U enchat -d enchat
```

## 8. 已知限制与未验证项（务必读）

### 未验证

1. **PostgreSQL DDL 未实机跑过**。所有集成测试用的是 H2（PostgreSQL 兼容模式）。DDL 本身用的都是标准语法（`BIGINT GENERATED BY DEFAULT AS IDENTITY`、`CREATE INDEX IF NOT EXISTS` 均需 PostgreSQL 10+），但**没有在真实 PostgreSQL 上执行过**。
   → 首次部署请务必跑 `deploy/verify.sh`，它的第 7 项会核对 9 张表是否都建出来了。若建表失败，日志里会有 JDBC 异常。

2. **Docker 构建未实机执行**（沙盒网络受限，拉不到 Gradle/基础镜像）。Dockerfile 按多阶段构建的标准写法编写，首次 `docker compose build` 可能仍需微调。

3. **`deploy.sh` / `verify.sh` / `backup.sh` 只做了语法检查**（`bash -n` 通过），未在真实主机上运行过。

### 设计局限（不是 bug，但上线前要心里有数）

4. **限速器是单进程内存态**。当前 `RateLimiter` 存在 `ConcurrentHashMap` 里，**多实例部署会完全失效**（每个实例各限各的）。要水平扩容必须换成 Redis。

5. **无 NTP/时间同步依赖但需留意**：端到端会话的密钥链依赖序号而非时间戳，时钟漂移影响较小，但群聊 epoch 与消息排序仍建议开启 chrony/ntp。

6. **头像文件存本地磁盘**，多实例或多机部署时不会共享。量大了应换对象存储。

7. **未做数据库迁移框架**：当前 `Db.migrate()` 只会 `CREATE TABLE IF NOT EXISTS`，**字段变更不会自动迁移**。将来改表结构需要自己写 ALTER 语句，或引入 Flyway/Liquibase。

8. **Argon2id 参数 64 MiB / t=3** 是 OWASP 量级。注册/登录并发上来时 CPU 和内存压力明显，需按实际压测调 `PasswordHash.SERVER_PARAMS` 或引入排队。

## 9. 上线检查清单

- [ ] 域名 A 记录已生效（`dig +short 你的域名` 返回服务器 IP）
- [ ] 80 / 443 端口已放行，8080 未对外暴露
- [ ] `.env` 中的 `DB_PASSWORD`、`PEPPER_B64` 已替换且已备份
- [ ] `server-identity.key` 所在卷已纳入定期备份
- [ ] 客户端 `app/build.gradle.kts` 已填入 ed25519 / x25519 并重新编译
- [ ] `deploy/verify.sh` 全部通过（尤其 WebSocket 与数据库表两项）
- [ ] `deploy/backup.sh` 已加入 crontab，且备份落异地
- [ ] 已确认 Nginx 日志与容器日志能被采集（排障时全靠它）
