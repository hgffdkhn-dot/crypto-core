# 已知缺陷与修复记录

## 缺陷 1：退出登录后崩溃，且之后启动必崩（只能卸载重装）

**严重程度**：致命。**现象**：设置页点「退出登录」→ App 直接关闭；之后再打开必闪退，只能卸载重装。

### 根因：4 个 bug 叠加

#### 1.1 主线程调用 Room（导致"点了就崩"）

`AppDatabase.clearAll()`：

```kotlin
suspend fun clearAll() {
    ...
    clearAllTables()   // Room 生成的【非 suspend】方法
}
```

`RoomDatabase.clearAllTables()` 是**非 suspend** 方法，Room 生成的实现第一行就是
`super.assertNotMainThread("clearAllTables")`。

`logout()` 跑在 `viewModelScope`（**主线程**）→ 主线程调用 → 抛
`IllegalStateException: Cannot access database on the main thread` → 未捕获 → 进程崩溃。

**关键点**：给函数加 `suspend` **不会**自动切线程。`clearAll()` 是 suspend，但它内部调用的
`clearAllTables()` 是普通方法，在哪个线程被调用就在哪个线程执行。

**修复**：`clearAll()` 整体用 `withContext(Dispatchers.IO)` 包裹。

#### 1.2 Keystore 缓存悬空（导致"重启也崩、只能卸载"）

`KeystoreVault.wipe()` 做了 `keyStore.deleteEntry(ALIAS)`，但包装密钥是
`private val wrappingKey: SecretKey by lazy { ... }` —— **一旦初始化就永久缓存**。

删除 Keystore 条目后，缓存的 `SecretKey` 变成"指向已删除条目"的悬空引用，
后续任何 `seal()` / `open()` 都抛异常。

更要命的是：崩溃后进程**不一定**重启（Application 仍存活），
这个坏状态会一直持续 → 每次启动都崩 → 只能清数据。

**修复**：
- `by lazy` 改为 `@Volatile private var cachedKey: SecretKey?`，`wipe()` 可显式失效
- `wipe()` **不再删除** Keystore 条目（见下）

#### 1.3 退出后无限重连

`ws.close()` 会把 `linkState` 置为 `IDLE`，立刻触发 `start()` 里注册的重连收集器：

```
close() → IDLE → reconnectAfter() → connect(pendingAuth)  // 用的是已失效的 token
```

形成 `close → IDLE → reconnect → 失败 → IDLE → ...` 的循环。

**修复**：
- 加 `@Volatile private var loggedOut`，重连前判断
- `WsClient.close(forgetAuth: Boolean)`：退出登录时丢弃 `pendingAuth`
- **注意不能无脑清 auth**：`close()` 在 Activity 配置变更（旋转屏幕）时也会被调用，
  那时必须保留 `pendingAuth` 才能自动重连，所以做成参数而非常量行为

#### 1.4 状态清理不彻底

`SettingsStore.clearSession()` 只删了 `SELF_UID` / `SELF_USER_ID` / `LAST_SYNC_SEQ`，
漏了昵称、头像、签名、以及 `E2EE_ENABLED_UIDS` / `E2EE_INTRO_SEEN_UIDS`。
换账号登录后会残留上一个账号的资料，且"已看过端到端介绍"的标记会让新账号不再弹说明。

**修复**：补全清理项。`HOST` / 主题 / 通知等属于**设备偏好**，跨账号保留，刻意不清。

### 附带修复

- `ViewModels.logout()` 加 `try/catch`，失败时停留在设置页并提示，不再冒泡崩溃
- `TOKEN_KEY` 从 private 提为 public，`AppContainer` 不再另写字面量
  （两处各写一遍，改名只改一边会导致 tokenProvider 恒为 null）
- `KeystoreVault.initCipher()` 增加密钥自愈：init 阶段抛 `GeneralSecurityException`
  时丢弃缓存重建重试一次

  ⚠️ 重试**只覆盖 init 阶段**是刻意的。密钥失效一定在 `cipher.init()` 暴露；
  数据损坏发生在 `doFinal()` 或参数校验阶段。若笼统包住整段加解密，
  一次"密文格式不对"就会误判成密钥失效，进而删掉一把**正常**的密钥 —— 不可逆，比崩溃更糟。

- `KeystoreVault.recoverIfBroken()` + `EnChatApplication.onCreate` 调用：
  启动自检，坏状态自动清掉让用户重新登录，**不需要卸载重装**

### 验证方式

1. 登录 → 设置 → 退出登录 → **不应关闭 App**，应跳到登录页
2. 重新打开 App → 应正常进入登录页（不再闪退）
3. 用另一个账号登录 → 昵称/头像应是新账号的，不是上一个账号残留
4. 退出登录后观察服务端日志 `journalctl -u enchat -f` → **不应**有持续重连
5. 登录状态下旋转屏幕 → 连接应保持或自动恢复（验证 `forgetAuth=false` 分支）
6. 断网 → 恢复网络 → 应自动重连

### 未验证

以上修复**未在真机上实测**（沙盒无 Android SDK，无法编译运行 `app/`）。
已做的验证：`tools/static-check-app.sh` 纯语法错误 0；crypto-core 77 项 + client-core 13 项回归测试通过。

请按上述 6 步在真机上验证。

## 缺陷 2：退出 App 重新进入要重新登录

**严重程度**：体验缺陷。**现象**：没退出过账号，但每次杀掉 App 重开都要重新登录。

### 根因

`AppNav` 的起始目的地写死成登录页：

```kotlin
NavHost(navController, startDestination = Route.LOGIN)
```

而 `ChatRepository.resumeIfPossible()`（从 Keystore 读 token、从 DataStore 读 uid 恢复会话）
**从来没有被调用过** —— 写好了但没人用。

### 修复

1. `ChatRepository` 新增 `sessionState: StateFlow<SessionState>`，三态：
   `UNKNOWN`（还没读完本地凭据）/ `LOGGED_IN` / `NOT_LOGGED_IN`
2. `start()` 里异步调用 `resumeIfPossible()` 并设置该状态
3. `MainActivity` 等待状态变为确定值：
   - `UNKNOWN` → 显示加载圈（避免先闪主界面再跳登录页）
   - `LOGGED_IN` → `AppNav(startLoggedIn = true)` 直接进主界面
   - `NOT_LOGGED_IN` → 走登录页
4. `afterAuth()` 里也要置 `LOGGED_IN` —— 否则登录成功后状态仍是 `NOT_LOGGED_IN`，
   会被下面的"踢下线"逻辑立刻弹回登录页

**为什么不能只判断"token 是否存在"**：读 Keystore / DataStore 是异步 I/O。
UI 一开始就假定已登录会先闪一下主界面再跳走；反过来假定未登录就得每次重新登录。
所以让启动流程显式等状态确定。

### 配套修复：令牌失效会被踢回登录页

自动恢复会话带来一个新风险：本地 token 还在但服务端已不认（过期/被吊销/服务端清库），
此时连接看起来正常，但所有业务请求都返回 401。

排查时发现 `handleFrame` **完全没处理** `AUTH_RESULT` 和 `ERROR` 帧 ——
服务端鉴权失败回的 ERROR 帧被直接忽略，于是会出现"假在线"：
显示已连接、但什么都做不了，而且重连循环永不停止。

修复：
- 处理 `AUTH_RESULT`：`ok=false` 时踢回登录页
- 处理 `ERROR`：`err == 401` 时踢回登录页
- `forceRelogin()` 不复用 `logout()` —— 后者会去调服务端 logout 接口，
  此刻令牌已无效，只会多一次必然失败的请求

**未验证**：沙盒无 Android SDK 无法真机验证。

### 验证方式

1. 登录后杀掉 App → 重开 → **应直接进主界面**，不要求登录
2. 设置 → 退出登录 → 重开 → 应要求登录
3. 让服务端 token 失效（重启服务端会保留会话，可等 30 天 TTL 或手动清 sessions 表）
   → App 应提示"登录已失效"并跳登录页，而不是卡在"已连接"

## 缺陷 3：设置页没有显示 UID

**严重程度**：体验缺陷。**现象**：设置页只能看到昵称，看不到自己的 UID，无法告知别人来加好友。

### 修复

- `SettingsViewModel` 暴露 `uidDisplay: StateFlow<String>`（`Protocol.formatUid` 9 位补零）
- 设置页账号区下方加一行「UID」，**点击可复制**到剪贴板并 Toast 提示

复制用 Android 原生 `ClipboardManager` 而非 `LocalClipboardManager`
（后者在较新 Compose 版本已废弃）。`getSystemService` 用 `as?` 转换，
某些定制 ROM 可能返回 null，避免直接 NPE。

### 未验证

同上，未真机验证。请确认：UID 显示为 9 位（如 `100000001`），点击后有"UID 已复制"提示。
