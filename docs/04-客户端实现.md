## 1. 模块划分

```
app/src/main/java/com/enchat/app/
├── EnChatApplication.kt / MainActivity.kt
├── di/AppContainer.kt        手写依赖容器（未引入 Hilt，避免 kapt 拖慢构建）
├── data/
│   ├── KeystoreVault.kt      Android Keystore AES-256-GCM 封装本地密钥
│   ├── SettingsStore.kt      DataStore：设置项 + 已开启端到端的好友集合
│   ├── local/               Room：会话/消息/联系人/好友请求/端到端会话状态
│   └── remote/
│       ├── ApiClient.kt      REST（OkHttp）
│       └── WsClient.kt      WebSocket + 传输层握手 + 自动重连
├── repo/
│   ├── ChatRepository.kt    业务编排（收发、端到端会话、同步、好友）
│   └── NetworkMonitor.kt    网络可用性（ConnectivityManager）
└── ui/
    ├── theme/Theme.kt       Material3 + Android 12+ 动态取色
    ├── AppNav.kt            导航
    ├── screens/             登录/注册、会话列表、聊天、联系人、设置
    ├── components/          连接状态条、端到端弹窗、头像
    └── vm/ViewModels.kt     ViewModel + 工厂

client-core/src/main/kotlin/com/enchat/clientcore/
├── ConnectionState.kt       连接状态机 + 重连退避（纯函数，可单测）
└── ConversationResolver.kt  会话列表解析 + 弹窗文案与展示时机（纯函数，可单测）
```

**为什么抽出 `client-core`**：需求里两条最容易写错的规则 —— 顶部横幅文案、以及"开启高级加密后好友列表多一条对话" ——
如果散落在 Compose 代码里就无法测试。抽成纯函数后，这两条规则有 13 项测试兜底。

## 2. 需求点的落点

| 需求 | 实现位置 |
|---|---|
| 顶部「连接中…」/「正在等待网络…」 | `client-core/ConnectionState.kt` 决定文案；`ui/components/ConnectionBanner.kt` 渲染 |
| 注册/登录（用户名 + 口令，允许字母） | `ui/screens/AuthScreens.kt`，校验走 `crypto-core` 的 `PasswordPolicy`（实时强度条 0–4 分） |
| UID、昵称、头像 | 联系人页展示 UID；设置页改昵称/签名；头像上传接口已通（`ChatRepository.uploadAvatar`），图片选择器下一轮接 |
| 好友机制 | `ContactsScreen` 按 UID 搜索 + 发送/接受/拒绝请求；`ChatRepository` 走 WS 帧 |
| 群聊 | **服务端已实现并测试**；客户端建群 UI 本轮未做（入口占位 `GroupEntryHint`） |
| 高级加密开关 | 聊天页右上角「设置」→「启用高级加密聊天」(`ChatViewModel.setE2eeEnabled`) |
| 开启后好友列表多一条对话 | `ConversationResolver.resolve()`：该好友同时出现标准会话 + 端到端会话 |
| 点进去弹窗（带锁图标） | `ui/components/E2eeIntroDialog.kt` + `E2eeIntroTracker` 控制"每个好友只弹一次" |
| 设置页 | `SettingsScreen`：账号/通知/聊天/隐私与安全/存储/外观/服务器/关于 |

### 2.1 连接状态判定

```
网络不可用                      → 正在等待网络…
网络可用 + 服务器链路未建立/断开  → 连接中…
网络可用 + 已 LINKED            → 不显示
```

`NetworkMonitor` 用 `ConnectivityManager.registerNetworkCallback` 监听"设备有没有网"；
`WsClient.linkState` 表示"服务器通不通"。两者在 `ChatRepository` 里 `combine` 后交给状态机。
**这两件事必须分开**：否则用户会对着"连接中"反复重启 App，而实际问题可能是开了飞行模式。

重连采用指数退避 + 抖动（1s → 30s 封顶），加抖动是为了避免服务器重启时的重连风暴。

### 2.2 端到端开启流程

1. 用户在聊天页右上角设置里打开开关
2. `ChatRepository.enableE2ee()`：拉取对方公钥包 → `verifySelfConsistent()` → `E2eeSession.createAsSender`
3. 发送 `E2EE_INIT` 帧（经各自 1:1 通道）
4. `SettingsStore.setE2eeEnabled(uid, true)` → 会话列表**多出一条**端到端会话
5. 首次进入该会话 → `E2eeIntroTracker.shouldShow()` 为真 → 弹出带锁图标的对话框

**"卸载后聊天将永远不复存在"为什么成立**：链密钥只存本地（Keystore 封装后落库），服务端只有密文，
卸载即删除本地库，历史消息确实无法恢复。这不是文案修辞，是实现的直接结果。

## 3. 本地存储与密钥保护

- **Keystore**：`KeystoreVault` 在 Android Keystore 里生成一把 AES-256-GCM 密钥，
  用它加密长期身份密钥（128B）、签名预密钥（132B）、一次性预密钥列表、以及序列化后的 `E2eeSession`。
  只能这样间接保护 —— Keystore 不能直接托管 X25519 私钥。
- **Room**：会话/消息/联系人缓存。**未加密整库**，这是已知取舍：
  - 标准模式消息本地存明文（与"服务器存明文"的设定一致）
  - 端到端模式本地只存密文
  - 退出登录清空全部表（`AppDatabase.clearAll`）
- 后续建议：接入 SQLCipher 加密整库。

## 4. 构建与运行

```bash
# 需要 JDK 17 + Android SDK 34 + Gradle 8.9
gradle :app:assembleDebug --no-daemon
gradle :app:installDebug  --no-daemon
```

**必须先做的事**（否则装上也连不上）：

1. 启动服务端，从控制台输出里拿到服务器长期公钥
2. 写入 `app/build.gradle.kts` 的 `SERVER_ED25519_PUB_B64` / `SERVER_X25519_PUB_B64`
   （或改为从 `local.properties` / CI 变量注入）
3. `DEFAULT_HOST`：`http://10.0.2.2:8080` 是模拟器访问宿主机的地址；真机请改成局域网 IP 或域名

客户端**故意**在公钥仍是占位值时抛异常启动失败 —— 宁可显式失败，也不要静默接受任意服务器。

清单里 `android:usesCleartextTraffic="false"`，即默认拒绝明文 HTTP。
本地联调若走 http，需要额外配置 network security config（下一轮补）。

## 6. 构建踩坑记录（已修 / 待验）

### 6.1 已修复：`Failed to find package 'tools'`（CI 挂在安装 SDK 阶段）

```
Warning: Failed to find package 'tools'
Error: The process '/usr/local/lib/android/sdk/cmdline-tools/16.0/bin/sdkmanager' failed with exit code 1
```

**根因**：`android-actions/setup-android@v3` 的 `packages` 默认值是 `tools platform-tools`。
Google 已把 legacy `tools` 包从 SDK 仓库下架，新版 cmdline-tools（16.0+）下
`sdkmanager` 找不到该包就直接返回退出码 1 —— 这一步发生在编译之前，所以"代码没问题，CI 也挂"。

**修复**（三处一起改）：

1. 升级到 `android-actions/setup-android@v4`：v4 的默认值已移除 `tools`，
   且即使被显式请求也只告警不再失败。
2. 仍显式传 `packages: 'platform-tools'`，双保险（v3 也能靠这个参数绕过）。
3. 删掉自己写的 `yes | sdkmanager --licenses` 步骤：新版 sdkmanager 已废弃该参数
   （提示 "The --licenses option is no longer needed"），且在 GitHub Actions 默认的
   `set -eo pipefail` 下 `yes |` 会因 SIGPIPE 返回 141。许可改由 action 的
   `accept-android-sdk-licenses` 处理。

另外显式安装编译所需组件，注意**包名里的分号是 shell 元字符**：

```bash
"$SM" --install "platforms;android-34" "build-tools;34.0.0"   # 必须加引号
```

不加引号会被拆成两条命令，报 `Failed to find package 'platforms'`。

### 6.2 已修复：AGP 插件找不到

```
Plugin [id: 'com.android.application', version: '8.5.2'] was not found
Searched in the following repositories: Gradle Central Plugin Repository
```

**原因**：`settings.gradle.kts` 里没有 `pluginManagement { repositories { google() } }`。
AGP 只发布在 Google Maven，不在 Gradle Plugin Portal。

**修复**：`settings.gradle.kts` 增加 `pluginManagement` 与 `dependencyResolutionManagement`，
统一声明 `google()` + `mavenCentral()` + `gradlePluginPortal()`，并用
`RepositoriesMode.FAIL_ON_PROJECT_REPOS` 禁止各模块私自声明仓库。
同时补上了 `client-core/build.gradle.kts`（此前缺失，会让 `include(":client-core")` 失败）。

### 6.3 已修复：Compose Compiler 与 Kotlin 版本不匹配

官方对照表 <https://developer.android.com/jetpack/androidx/releases/compose-kotlin>：

| Compose Compiler | 目标 Kotlin |
|---|---|
| 1.5.14 | 1.9.24 |
| 1.5.15 | **1.9.25** |

本项目原为 Kotlin 1.9.24 + CC 1.5.15，即使 AGP 找到了也会接着报
`This version (1.5.15) of the Compose Compiler requires Kotlin version 1.9.25`。
已把 Kotlin 升到 **1.9.25**（与 CC 1.5.15 对齐）。

### 6.4 已修复：两处 API 用了高于当前 BOM 的签名

BOM `2024.06.00` → material3 `1.2.1`，以下写法都不存在：

- `LinearProgressIndicator(progress = { ... })` —— lambda 形式是 1.5.0+ 才有的，已改回 `progress = Float`
- 非可点击的 `Surface(contentDescription = ...)` —— 只有带 `onClick` 的重载才有该参数，已移除

### 6.5 已修复：Android 测试依赖与 Room schema 路径

- `app/` 原本声明 `testImplementation(junit-jupiter)`。Android 单元测试源集默认只认 JUnit4，
  JUnit5 需额外引入 `android-junit5` 插件。已改为 `junit:junit:4.13.2`。
- `room.schemaLocation` 写在 `gradle.properties` 里无效（`$projectDir` 不会插值），
  已改为在 `app/build.gradle.kts` 用 `kapt { arguments { arg(...) } }` 传入。

### 6.6 已加固：无 Android SDK 也要能跑 JVM 模块

Gradle 的配置阶段会配置**所有**模块，`:app` 一旦被配置就需要 AGP 找 Android SDK。
在 `gradle.properties` 里加了 `org.gradle.configureondemand=true`，
这样 `gradle :crypto-core:build` / `:server:test` 不会去配置 `:app`。

### 6.7 仍待首次构建验证（未验证，按经验列出）

1. **`android-actions/setup-android@v4` 是否可用**：依据是该仓库 README 的 v4 示例。
   若 `v4` tag 不可用，退回 `v3` 并保留 `packages: 'platform-tools'` 亦可绕过。
2. **Material3 API**：`TopAppBar`、`NavigationBar`、`ListItem`、`AlertDialog(icon=)` 均已
   `@OptIn(ExperimentalMaterial3Api::class)`；`HorizontalDivider` 已核实存在于 material3 1.2.1。
   `AlertDialog(icon = ...)` 在 1.2.x 才有，若报未解析参数需降到 `title`/`text` 两参数写法。
3. **图标**：依赖了 `material-icons-extended`（体积较大，release 开启 R8 会裁剪）。
4. **Navigation Compose 参数类型**：`NavType.LongType/IntType/StringType` 与路由拼接需一致。
5. **`buildFeatures.buildConfig = true`**：AGP 8 起默认关闭，已在脚本里显式打开。
6. **BouncyCastle 在 Android 上**：用的是 `bcprov-jdk18on`（面向 JDK 1.8+）。
   Android 项目更常见的是 `bcprov-jdk15to18`；`jdk18on` 通常可用，但**真机上未实测**，
   若运行时出现 `NoClassDefFoundError`，改回 `bcprov-jdk15to18` 即可（API 完全一致）。
