## 2. 需求点的落点

| 需求 | 实现位置 |
|---|---|
| 顶部「连接中…」/「正在等待网络…」 | `client-core/ConnectionState.kt` 决定文案；`ui/components/ConnectionBanner.kt` 渲染 |
| 注册/登录（用户名 + 口令，允许字母） | `ui/screens/AuthScreens.kt`，校验走 `crypto-core` 的 `PasswordPolicy`（实时强度条 0–4 分） |
| UID、昵称、头像 | 联系人页展示 UID；设置页改昵称/签名；头像上传接口已通（`ChatRepository.uploadAvatar`），图片选择器下一轮接 |
| 好友机制 | `ContactsScreen` 按 UID 搜索 + 发送/接受/拒绝请求；`ChatRepository` 走 WS 帧 |
| 群聊 | **服务端已实现并测试**；客户端建群 UI 本轮未做（入口占位 `GroupEntryHint`） |
| 高级加密开关 | 聊天页右上角「设置」→「启用高级加密聊天」(`ChatViewModel.setE2eeEnabled`) |
| 开启后好友列表多一条对话 | `ConversationResolver.resolve()`：该好友同时出现标准会话 + 端到端会话 |
| 点进去弹窗（带锁图标） | `ui/components/E2eeIntroDialog.kt` + `E2eeIntroTracker` 控制"每个好友只弹一次" |
| 设置页 | `SettingsScreen`：账号/通知/聊天/隐私与安全/存储/外观/服务器/关于 |

### 2.1 连接状态判定

```
网络不可用                      → 正在等待网络…
网络可用 + 服务器链路未建立/断开  → 连接中…
网络可用 + 已 LINKED            → 不显示
```

`NetworkMonitor` 用 `ConnectivityManager.registerNetworkCallback` 监听"设备有没有网"；
`WsClient.linkState` 表示"服务器通不通"。两者在 `ChatRepository` 里 `combine` 后交给状态机。
**这两件事必须分开**：否则用户会对着"连接中"反复重启 App，而实际问题可能是开了飞行模式。

重连采用指数退避 + 抖动（1s → 30s 封顶），加抖动是为了避免服务器重启时的重连风暴。

### 2.2 端到端开启流程

1. 用户在聊天页右上角设置里打开开关
2. `ChatRepository.enableE2ee()`：拉取对方公钥包 → `verifySelfConsistent()` → `E2eeSession.createAsSender`
3. 发送 `E2EE_INIT` 帧（经各自 1:1 通道）
4. `SettingsStore.setE2eeEnabled(uid, true)` → 会话列表**多出一条**端到端会话
5. 首次进入该会话 → `E2eeIntroTracker.shouldShow()` 为真 → 弹出带锁图标的对话框

**"卸载后聊天将永远不复存在"为什么成立**：链密钥只存本地（Keystore 封装后落库），服务端只有密文，
卸载即删除本地库，历史消息确实无法恢复。这不是文案修辞，是实现的直接结果。

## 3. 本地存储与密钥保护

- **Keystore**：`KeystoreVault` 在 Android Keystore 里生成一把 AES-256-GCM 密钥，
  用它加密长期身份密钥（128B）、签名预密钥（132B）、一次性预密钥列表、以及序列化后的 `E2eeSession`。
  只能这样间接保护 —— Keystore 不能直接托管 X25519 私钥。
- **Room**：会话/消息/联系人缓存。**未加密整库**，这是已知取舍：
  - 标准模式消息本地存明文（与"服务器存明文"的设定一致）
  - 端到端模式本地只存密文
  - 退出登录清空全部表（`AppDatabase.clearAll`）
- 后续建议：接入 SQLCipher 加密整库。

## 4. 构建与运行

```bash
# 需要 JDK 17 + Android SDK 34 + Gradle 8.9
gradle :app:assembleDebug --no-daemon
gradle :app:installDebug  --no-daemon
```

**必须先做的事**（否则装上也连不上）：

1. 启动服务端，从控制台输出里拿到服务器长期公钥
2. 写入 `app/build.gradle.kts` 的 `SERVER_ED25519_PUB_B64` / `SERVER_X25519_PUB_B64`
   （或改为从 `local.properties` / CI 变量注入）
3. `DEFAULT_HOST`：`http://10.0.2.2:8080` 是模拟器访问宿主机的地址；真机请改成局域网 IP 或域名

客户端**故意**在公钥仍是占位值时抛异常启动失败 —— 宁可显式失败，也不要静默接受任意服务器。

清单里 `android:usesCleartextTraffic="false"`，即默认拒绝明文 HTTP。
本地联调若走 http，需要额外配置 network security config（下一轮补）。

## 6. 构建踩坑记录（已修 / 待验）

### 6.1 已修复：`Failed to find package 'tools'`（CI 挂在安装 SDK 阶段）

```
Warning: Failed to find package 'tools'
Error: The process '/usr/local/lib/android/sdk/cmdline-tools/16.0/bin/sdkmanager' failed with exit code 1
```

**根因**：`android-actions/setup-android@v3` 的 `packages` 默认值是 `tools platform-tools`。
Google 已把 legacy `tools` 包从 SDK 仓库下架，新版 cmdline-tools（16.0+）下
`sdkmanager` 找不到该包就直接返回退出码 1 —— 这一步发生在编译之前，所以"代码没问题，CI 也挂"。

**修复**（三处一起改）：

1. 升级到 `android-actions/setup-android@v4`：v4 的默认值已移除 `tools`，
   且即使被显式请求也只告警不再失败。
2. 仍显式传 `packages: 'platform-tools'`，双保险（v3 也能靠这个参数绕过）。
3. 删掉自己写的 `yes | sdkmanager --licenses` 步骤：新版 sdkmanager 已废弃该参数
   （提示 "The --licenses option is no longer needed"），且在 GitHub Actions 默认的
   `set -eo pipefail` 下 `yes |` 会因 SIGPIPE 返回 141。许可改由 action 的
   `accept-android-sdk-licenses` 处理。

另外显式安装编译所需组件，注意**包名里的分号是 shell 元字符**：

```bash
"$SM" --install "platforms;android-34" "build-tools;34.0.0"   # 必须加引号
```

不加引号会被拆成两条命令，报 `Failed to find package 'platforms'`。

### 6.7 已修复：org.json `put` 的重载歧义

```
e: .../ChatRepository.kt:562:54 Overload resolution ambiguity:
  public open fun put(p0: String!, p1: Any!): JSONObject!
  public open fun put(p0: String!, p1: Long): JSONObject!
```

org.json 的 `JSONObject` 同时有 `put(String, Object)` 与 `put(String, int/long/boolean/double)`
两套重载，Kotlin 在几种情况下会无法抉择。

**修复**：新增 `data/remote/Json.kt`：

```kotlin
fun jsonObjectOf(vararg pairs: Pair<String, Any>): JSONObject = JSONObject().apply {
    pairs.forEach { (key, value) -> put(key, value) }
}
```

值统一声明为 `Any`，只会命中 `put(String, Object)`，从类型层面消除歧义。
`ApiClient.post` 的 lambda 接收者也从 `JSONObject` 改成 `MutableMap<String, Any>`（同一原因）。
全部链式 `JSONObject().put(..).put(..)` 已替换。

> 注：本地用 org.json 20240303 + Kotlin 1.9.24 实测，**链式 `put` 本身并不歧义**。
> CI 报在 562 行是因为该行 `seq` 的类型来自 `com.enchat.app.data`（该包当时整体编译失败），
> 是**错误类型引发的次级报错**——所以真正的根因还在下面。

`ConversationEntity.avatarUrl` 没有默认值，而 `onDeliver()` 里的兜底构造没传它。

### 6.9 已加固：Room schema 导出

`exportSchema = true` 但 `room.schemaLocation` 参数没被 kapt 正确接收时，
Room 会以"schema 导出目录未提供"中断构建。项目尚未需要迁移脚本，先设为 `false`。

### 6.10 已加固：按 SDK 是否存在决定是否纳入 `:app`

AGP 在**配置阶段**就要定位 Android SDK。若把 `:app` 无条件 `include`，
没有 SDK 的机器上连 `:crypto-core` / `:server` 都构建不了。
改为条件 include：

```kotlin

if (androidSdkDetected) include(":app")
```

同时移除了 `org.gradle.configureondemand=true` —— 它对 Android/kapt 有已知副作用，
用条件 include 替代更可控。

### 6.11 已修复（重点）：`runCatching { suspendFun() }` 编译不过

```kotlin
viewModelScope.launch {
    runCatching { repo.login(username, password) }   // ❌ 编译错误
        .onSuccess { ... }
}
```

Kotlin 规则：suspend 函数只能在 **suspend 上下文**里调用。
`runCatching` 的 lambda 是**普通非 suspend lambda**，
即使它词法上位于 `launch {}` 内部，也**不能**在里面调 suspend 函数。报：

```
suspend function 'login' should be called only from a coroutine or another suspend function
```

这是个隐蔽点：肉眼看着"都在 launch 里"，但 `runCatching`/`let`/`apply` 这类
接收普通 lambda 的高阶函数都会**切断** suspend 上下文。

**修复**：`runCatching { ... }.onSuccess/onFailure` 一律改成 `try/catch`。
已修 7 处：`ViewModels`(register/login/findUser/updateProfile)、
`ChatRepository`(logout/uploadKeys)、`ApiClient`(logout)。

> 排查技巧：本地静态检查时，`viewModelScope.launch { suspendFun() }` 这种**合法**写法
> 会因为 `viewModelScope` 未解析而被误报成同类错误。区分方法是看被调函数是否
> 被 `runCatching`/`let`/`apply` 等**非 suspend lambda** 包住 —— 是的话才是真 bug。

### 6.12 已修复：类型推断脆弱点显式化

以下写法在**上游类型解析失败时**会退化成难以定位的 `K`/`T` 推断错误，掩盖真正原因：

| 原写法 | 问题 | 改法 |
|---|---|---|
| `combine(a, b, c) { x, y, z -> }` | 报 `Cannot infer a type for this parameter` | `combine<A, B, C, R>(...)` 显式泛型 |
| `conversations.associate { ... }` | 报 `Not enough information to infer type variable K` | 显式 `Map<Pair<Long, Int>, X>` |
| `p[KEY] ?: emptySet()` | `emptySet()` 无类型实参 | `emptySet<String>()` |
| `read(Keys.X, default)` | 报 `not enough information to infer type variable T` | `read<String>(...)` 显式类型实参 |

显式化之后，若类型真的解析不了，报错会**直接点名实体类**，而不是报推断失败。

同时把 `com.enchat.app.data.local.FriendRequestEntity` 这类**全限定名**改成 import + 简单名 ——
包解析失败时全限定名的报错更难读。

### 6.13 已加固：CI 固定打印前 60 条 Kotlin 错误

Kotlin 按文件顺序列出错误，`data/` 排在 `ui/` 之前。
根因往往在日志最前面，却被 Gradle 的失败摘要顶掉。
已在 workflow 增加 `Print first Kotlin errors` 步骤（`if: failure()`），
固定打印前 60 条 `^e: ` 以及依赖/kapt/AGP 类错误。

### 6.14 已修复【本轮根因】：`.gitignore` 里的裸 `data/` 把整个源码包排除出仓库

现象（CI 第一条错误，位于 `di/AppContainer.kt`）：

```
Unresolved reference: data          ← import com.enchat.app.data.X 的 "data" 段
Unresolved reference: SettingsStore
Unresolved reference: WsClient / ApiClient / ChatDao / LinkState / jsonObjectOf ...
```

**判断依据**：`data/` 下的文件（`SettingsStore.kt`、`KeystoreVault.kt`、`Entities.kt`、`Dao.kt`、
`AppDatabase.kt`、`ApiClient.kt`、`WsClient.kt`）**一条错误都没报**。
如果它们在源码树里却编译失败，Kotlin 一定会在这些文件里报错（它们按字母序排在 `di/` 之前）。
既不报错又不可解析 ⇒ **这些文件根本不在编译源集里**。

**根因**：仓库根的 `.gitignore` 有一条不带前导斜杠的 `data/`：

```gitignore
data/     # ❌ 匹配任意深度的 data 目录，包括 app/src/main/java/com/enchat/app/data/
```

gitignore 中不含 `/` 的模式会匹配**任意层级**的同名目录。于是整个
`com.enchat.app.data` 包（含 `data.local` / `data.remote`）从未被提交，
Actions 检出后自然不存在。

**修复**：

1. `.gitignore` 中所有目录模式加前导 `/` 锚定到仓库根：`/data/`、`/libs/`、`/build/` …
2. 追加兜底反忽略：`!app/src/main/java/**`、`!app/src/main/res/**`
3. 重新提交此前被忽略的文件：

```bash
git add -A
git ls-files app/src/main/java/com/enchat/app/data/   # 必须列得出 8 个文件
git commit -m "chore: 修复 .gitignore 误排除 app data 源码包"
```

自查命令（本地就能跑）：

```bash
git check-ignore -v app/src/main/java/com/enchat/app/data/SettingsStore.kt
# 有输出 = 仍被忽略；无输出 = 正常
```

4. CI 增加 `Verify all source files are present` 预检步骤：
   逐个 stat 关键源文件，缺失即失败并打印上述排查命令。
   这类"文件静默缺失"以前不会有任何提示，只会表现为整包 unresolved。

> **教训**：我之前几轮把 `Unresolved reference: data` 当成"级联错误"去上游找原因，
> 方向错了。区分方法很简单 —— 看被引用包自己的文件**有没有报错**：
> 一条都没有，就是文件不在；有报错，才是真编译失败。

### 6.15 已修复：companion object 成员用实例调用

```kotlin
vault.seal(spk.toStorageBytes())          // ❌ 编译错误
```

### 6.16 已新增：本地静态检查脚本 `tools/static-check-app.sh`

沙盒无 Android SDK，`app/` 无法真编译，直接看 kotlinc 输出会有上千条
`unresolved reference`（全是 androidx/compose/room/okhttp/coil 缺失），真错误被淹没。

脚本做法：收集 app 源码里所有 `androidx.*` / `android.*` / `coil` 导入的简单名
外加 okhttp3/okio 等常见第三方名作为白名单，其余错误一律打印：

```bash
./tools/static-check-app.sh
```

当前状态：**纯语法错误 0**；剩余条目均为缺 Android 依赖导致的级联
（`popUpTo`/`item`/`onCreate`/`settingsDataStore.edit` 等）。

### 6.17 仍待验证（未验证 / 需完整日志定位）

`:app` 首次编译时 `com.enchat.app.data` 包整体未解析（表现为
`Unresolved reference: data`、以及下游 `FriendRequestEntity` / `MessageEntity` 全部 unresolved）。
这类"整个包不可见"通常是**包内某个文件的 import 或注解处理失败**引发的级联。
已做的加固见 6.2 / 6.7 / 6.8 / 6.9；若仍失败，请用下面命令拿到第一条真正的错误：

```bash
gradle :app:assembleDebug --console=plain 2>&1 | grep -E "^e: " | head -40
# 或只看 data 包与 kapt 相关
gradle :app:assembleDebug --console=plain 2>&1 | grep -E "data/(local|remote)|kapt" | head -30
```

最可能的三类根因与对应处理：

| 若首条错误是 | 说明 | 处理 |
|---|---|---|
| Room/kapt 点名某个 Entity | 实体定义或处理器参数有问题 | 把实体简化：字段加 `@ColumnInfo`、去掉多列 `Index` |
| `Unresolved reference: androidx.room` 等 | 依赖没解析到 | 检查 `google()` 是否在 `dependencyResolutionManagement` 里（已在） |
| `Unresolved reference: BuildConfig` | 生成的 BuildConfig 没生效 | 确认 `buildFeatures { buildConfig = true }`（已开） |

其余（按经验列出）：

1. **`android-actions/setup-android@v4` 是否可用**：依据是该仓库 README 的 v4 示例。
   若 `v4` tag 不可用，退回 `v3` 并保留 `packages: 'platform-tools'` 亦可绕过。
2. **Material3 API**：`TopAppBar`、`NavigationBar`、`ListItem`、`AlertDialog(icon=)` 均已
   `@OptIn(ExperimentalMaterial3Api::class)`；`HorizontalDivider` 已核实存在于 material3 1.2.1。
   `AlertDialog(icon = ...)` 在 1.2.x 才有，若报未解析参数需降到 `title`/`text` 两参数写法。
3. **图标**：依赖了 `material-icons-extended`（体积较大，release 开启 R8 会裁剪）。
4. **Navigation Compose 参数类型**：`NavType.LongType/IntType/StringType` 与路由拼接需一致。
5. **`buildFeatures.buildConfig = true`**：AGP 8 起默认关闭，已在脚本里显式打开。
6. **BouncyCastle 在 Android 上**：用的是 `bcprov-jdk18on`（面向 JDK 1.8+）。
   Android 项目更常见的是 `bcprov-jdk15to18`；`jdk18on` 通常可用，但**真机上未实测**，
   若运行时出现 `NoClassDefFoundError`，改回 `bcprov-jdk15to18` 即可（API 完全一致）。
